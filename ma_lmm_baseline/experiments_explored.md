# Experiments Explored — MA-LMM Baseline

This document summarises the experiments tried beyond the vanilla MA-LMM
baseline inference pipeline.

---

## Baseline — Vanilla MA-LMM inference

**Script:** `run_inference.sh` → `scripts/infer.py`

Run MA-LMM end-to-end on full Ego4D videos across three duration splits
(10 min, 30 min, 60 min).  The model's memory bank (default: 40 frames)
compresses temporal context into a fixed number of visual tokens; Vicuna then
generates a single caption per video.

**Key settings:**
| Parameter | Default |
|---|---|
| `num_frames` | 80–100 |
| `memory_bank_length` | 40 |
| Duration splits | 10 min, 30 min, 60 min |

**Output:** `outputs/captions_{10min,30min,60min}.json`

## Experiment 1 — Hierarchical chunk-level captioning

**Scripts:** `run_chunked.sh` → `scripts/infer_chunked.py`
**Orchestrator:** `run_all_sequential.py`

**Motivation.**
MA-LMM's memory bank compresses hour-long context into 32 visual tokens — a
lossy operation for very long videos.  An alternative is to divide a video
into short temporal chunks, caption each chunk independently with MA-LMM,
then merge the chunk captions into a single video-level summary using the
already-loaded Vicuna LLM.

**Configurations explored for a 60-min video:**

| Config | Chunks | Captions before merge |
|---|---|---|
| 10-min chunks | 6 | 6 → 1 summary |
| 5-min chunks | 12 | 12 → 1 summary |
| 2-min chunks | 30 | 30 → 1 summary |
| 1-min chunks | 60 | 60 → 1 summary |

1-min and 2-min chunk runs were done on 30-min videos to keep total runtime
manageable (CHUNK_MINS=1, VARIANT=30min).

**How it works (`scripts/infer_chunked.py`):**
1. Sort all frames in a video directory chronologically.
2. Divide into fixed-size temporal windows
   (`chunk_duration_min × video_fps` frames each).
3. Run MA-LMM on each chunk independently (same `num_frames` subsampling
   per chunk, same `memory_bank_length`).
4. Feed all chunk captions as text to Vicuna for a single-paragraph summary.
   For large chunk counts (> 15), hierarchical summarisation is applied —
   captions are grouped into batches of 15, each batch is summarised, then
   the batch summaries are merged — keeping every Vicuna prompt within the
   2 048-token context window.

**Running:**
```bash
conda activate malmm_baseline
bash run_chunked.sh                    # 10-min chunks, 60-min videos (default)
CHUNK_MINS=1  bash run_chunked.sh      # 1-min chunks
VARIANT=30min CHUNK_MINS=2 bash run_chunked.sh
```

**Orchestrator (`run_all_sequential.py`)** runs all four configurations in
sequence with automatic per-video retry logic (up to 8 retries), skipping
already-finished videos between attempts.

**Output:** `outputs/exp1_chunked/<CHUNK_MINS>min_chunks/<video_id>.json`

Each JSON contains per-chunk captions (with timing and GPU memory stats)
and the final Vicuna-generated video-level summary.

**Observations / known issues:**
- GPU peak memory per chunk is ~15–16 GB (H100 80 GB), well within budget.
- Very short chunks (1 min, ~600 frames → 80 subsampled) lose inter-chunk
  continuity; Vicuna's merge step partially recovers it.
- Vicuna context overflow with 60+ raw captions is addressed by hierarchical
  grouping (groups of 15).

## Experiment 2 — Frame-budget vs quality / compute trade-off sweep

**Scripts:** `run_frame_sweep.sh` → `scripts/infer.py` (with param overrides)
**Analysis:** `scripts/plot_sweep.py`

**Motivation.**
The paper's baseline uses 80–100 uniformly sampled frames and MBL=40.
Increasing these parameters is expected to improve caption quality but
increases inference time and GPU memory.  This sweep characterises the
quality–compute Pareto frontier.

**Configuration grid (run on 10-min videos, 5 videos):**

| `num_frames` | `memory_bank_length` | Label |
|---|---|---|
| 100 | 40 | baseline (paper default) |
| 100 | 80 | larger memory, same input frames |
| 200 | 40 | 2× frames, baseline memory |
| 200 | 80 | 2× both |
| 200 | 160 | 2× frames, full memory (no compression fires) |
| 400 | 80 | 4× frames, 2× memory |
| 400 | 160 | 4× frames, 4× memory |
| 400 | 320 | 4× frames, near-full memory |

**Running:**
```bash
conda activate malmm_baseline
bash run_frame_sweep.sh       # runs all 8 configs, skips completed ones
```

**Plots generated by `scripts/plot_sweep.py`:**

| Plot file | Contents |
|---|---|
| `inference_time.png` | Wall-clock time vs `num_frames`, one line per MBL |
| `gpu_memory.png` | GPU peak memory vs `num_frames`, one line per MBL |
| `caption_quality.png` | ROUGE-L vs `num_frames` (requires Ego4D narration.json) |
| `quality_vs_compute.png` | Pareto scatter: ROUGE-L vs inference time per config |

**Observations / known issues:**
- The 400-frame configs require ≥ 40 GB VRAM; cap at 200 frames on 24 GB GPUs.
- Already-completed configs are skipped automatically on re-run.

## Evaluation — ROUGE / BERTScore against Ego4D ground truth

**Script:** `scripts/evaluate.py`

Compares output captions from two inference pipelines (vanilla MA-LMM via
`infer.py` and the two-stage workaround via `infer_v2.py`) against Ego4D
ground-truth narration summaries (`narration_pass_1` from
`ego4d/.../narration.json`).

**Metrics:** ROUGE-1, ROUGE-2, ROUGE-L, BERTScore (roberta-large).

**Usage:**
```bash
python scripts/evaluate.py \
    --malmm    outputs_latest_2/captions_10min_malmm.json \
    --twostage outputs_v2_100frames/captions_10min.json \
    --narration /path/to/ego4d/v2/annotations/narration.json \
    --ann_path  data/annotations/ego4d_10min.json
```

Ground truth is built by filtering `narration_pass_1` summaries to the
video's actual duration (derived from frame count and FPS), then
concatenating them into a single reference string.
